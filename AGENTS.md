# Contributor requirements

Read `CLAUDE.md` for the full operating rules. Two that are absolute:

**1. Documentation is never stale.** If a change alters a fact stated in the
documentation, updating that documentation is part of the **same PR diff**.
Always — not a follow-up, not a separate PR, not a TODO. A PR that changes
behaviour, configuration, environment scoping or a documented invariant without
updating the affected docs in the same diff is **incomplete** and does not go
up. Check `MASTER-PLAN.md`, `CLAUDE.md`, `AGENTS.md`, `HANDOVER.md`,
`SETUP.md`, `DEPLOY.md` and `docs/` before opening anything.

**2. Sale notifications and lead notifications follow opposite rules.** A sale
notification fires only when Stripe confirms payment. Lead notifications
(wholesale enquiries, arrangement requests, waitlist signups) are independent of
payment and always fire — silencing one is a regression, not a fix. See issue
\#22.

in it; they will be overwritten.
